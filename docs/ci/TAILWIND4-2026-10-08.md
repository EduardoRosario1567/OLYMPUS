# Tailwind 4 — migração de segurança

Base: PR #2, commit 78dc885b7418974e9e4fc198041e60122bbb839e. Este PR deve ser revisado depois do PR #2; não integra automaticamente à main.

## Mudanças

- Tailwind CSS e @tailwindcss/postcss 4.3.3, tailwind-merge 3.7.0.
- PostCSS usa o plugin dedicado; autoprefixer foi removido da cadeia.
- globals.css importa Tailwind, declara fontes locais de classes, variante dark e tema CSS. A configuração TS antiga foi substituída pelo tema CSS.
- Paleta de cores v3, raios personalizados, cores de bordas/placeholders e cursor de botões preservados; classes de outline, blur e raio renomeadas conforme o guia de migração.
- Next atualizado para 16.3.8 após novos avisos publicados na auditoria atual, incluindo GHSA-cjq9-62q9-8jv4. O teste exige esse piso e consistência com o lockfile.
- Contrato de navegador verifica dimensões do logo e barra lateral, comportamento responsivo e produz capturas de desktop claro/escuro e mobile. O CI publica essas evidências como artifact.

## Validação local

- npm install e build de produção/TypeScript: aprovados; 13 páginas geradas.
- npm audit completo: zero vulnerabilidades conhecidas na consulta de 2026-10-08. A cadeia antiga tinha sete alertas do Tailwind; novos avisos do Next foram corrigidos pelo patch 16.3.8.
- 19 testes direcionados de dependências e failover: aprovados.
- Sintaxe do contrato JavaScript, YAML/Bash do workflow e whitespace: aprovados.
- Browser local continua indisponível neste ambiente; validação em Chromium e capturas dependem do CI remoto. Não se declara aprovação visual antecipadamente.

## Compatibilidade e limites

Tailwind 4 exige Safari 16.4+, Chrome 111+ ou Firefox 128+. Não houve teste em Safari ou Firefox neste patch. Uma auditoria sem alertas não é certificação de segurança.

Na execução anterior do PR #2 (37712782887), a suíte e o isolamento de catálogo passaram, mas o gate macos-command-contract bloqueou version_healthcheck e owned_process_checks. Esses requisitos do launcher já falham na base; a execução inicial desta migração também não modificava os comandos. O complemento abaixo corrige o inicializador mantendo o gate ativo.

## Complemento — compatibilidade do piloto macOS 12 (2026-10-08)

- A candidata aceita Node >=22.23.2 <23 ou >=24.15 <25. Build e auditoria local passaram com Node 22.23.2; o CI valida as duas séries e usa Node 22 no navegador real.
- Instalador e inicializador procuram Python 3.11+ separado do Python do sistema; a seleção respeita OLYMPUS_PYTHON. Não substituem nem removem uma venv antiga. A máquina do piloto tem somente Python 3.9.6 confirmado e ainda precisa de um intérprete compatível para o smoke macOS.
- Funções de healthcheck usam os nomes exigidos pelo contrato. A propriedade e existência do processo são conferidas antes dos sinais TERM e KILL. Se a identidade mudar, o inicializador recusa encerrar o processo.
- Seis testes de comportamento cobrem processos estrangeiros/desaparecidos, mudança de identidade antes de TERM/KILL e respostas de versão/produto. Gate estático macOS aprovado localmente. Isso não equivale a execução no macOS.
- Ao desbloquear a etapa seguinte, o teste blind_mission_gate revelou fixture desatualizada: o modelo simulado não criava docs/delivery-concept.md. Agora cria o documento antes do HTML e a evidência continua independente. O retorno do clique Playwright foi normalizado para o campo result que o verificador exige. Não se removeu nenhum requisito do produto.
- Gate de missão cega aprovado localmente com jsdom-runtime; Chromium será validado pelo CI. Gate core failover/checkpoint aprovado. A versão do produto continua 3.0.8; esta branch é uma candidata de dependências, não uma release promovida.
